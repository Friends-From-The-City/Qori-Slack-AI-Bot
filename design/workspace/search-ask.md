# Search + Ask Qori — unified surface (UX-2 §28, supersedes separate-nav answer)

One surface, one scope model: Search narrows the authorized corpus; Ask Qori reasons over that SAME scoped corpus. Not a floating chatbot.

- Entry: one nav item ("Search & Ask"), one input. Typing filters entities live (CURRENT: variable/entity search; full-text = NOT IMPLEMENTED, gap). Asking (natural-language question or explicit Ask action) runs LLM interpretation over the scoped corpus (CURRENT: /qori-ask cross-study variable search + interpretation).
- Scope bar always visible: org/project/study filters; the answer states its scope ("Answered from Claims Portal Redesign — 2 studies").
- Answer anatomy: answer text with citation chips (Phase 4B grammar) -> supporting findings list with evidence counts -> "why these results" (matched variables/entities) -> traceability entry points (peek/trail).
- No answer without provenance: if the corpus can't support it, say so ("No accepted findings address this — 2 candidate themes mention it").
- Keyboard: / focuses search anywhere; results list arrow-navigable.
