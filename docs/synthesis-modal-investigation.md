## 1. Current modal state

### Where the modal is defined

- **Modal UI:** `backend/src/helpers/slack/ui/researchSynthesisModal.js`

### What input options it currently surfaces

The modal renders 6 sections in order:

| Section | Data source | Block ID | Required? |
|---------|-------------|----------|-----------|
| Study selector | `getStudiesByUser()` from `research_studies` table | `study_select_block` | Yes |

**No analysis-layer files are surfaced.** Nothing from `04-analysis/` appears in the modal.

## 2. Current input flow

Complete path from Slack click to LLM prompt:

```
User selects study
  → handleStudySelectionChange fires
  → 3 service calls: sessionSummaries, studyNotes (transcript=true), stakeholderGuides
  → GitHub validation: readFolderContents checks each file still exists, prunes stale DB records
  → Modal re-renders with populated checkbox lists

User checks files + selects analysis method + clicks Submit
  → handleResearchSynthesisSubmission fires
  → Reads view.state.values for all checked options
  → Strips prefixes (summary_, transcript_, guide_) to get DB IDs
  → Re-fetches DB records, filters to selected IDs
  → For each selected file: fetchFileFromRepoByPath(GITHUB_REPO, file.file_path) → gets raw content
  → combined_file_content = all file contents joined with '\n\n---\n\n'
  → detected_files = list of relative paths (one per line)
  → analysisData object passed to processYamlTemplate
  → YAML template's {{combined_file_content}} receives all the content
  → LLM processes and generates output
```

**Key insight:** The `fetchFileFromRepoByPath` call works with any GitHub path. There is zero type discrimination — if a file path is in `allFiles`, it gets fetched and included in `combined_file_content`. The constraint is purely about *which files appear as checkbox options in the modal*.

- **Journey map** needs affinity map themes to identify cross-participant stage patterns
- **Personas** need affinity map to group behavioral patterns across participants
- **Design opportunities** need all prior synthesis to generate HMW statements
- **Service blueprint** needs stakeholder synthesis + journey map for backstage/frontstage mapping
- **Research readout** already handles this via its own `readoutHandler.js` scanning — but synthesis templates don't have the same access

## 4. Proposed solution

### Recommended approach: GitHub folder scan + new modal section

**Option 3 (auto-include with informational display)** is the cleanest:

1. When a study is selected, scan `04-analysis/` subfolders via `readFolderContents` (same mechanism already used in `readoutHandler.js` and the GitHub validation step)
2. Display discovered analysis files in a new **"Prior Analysis (optional)"** checkbox section in the modal
3. Auto-check files that are recommended for the selected analysis method
4. Include help text explaining what each file type contributes

### Why not the other options

- **Single "Include analysis files" checkbox** — too coarse. A user running personas shouldn't necessarily include the service blueprint. Granular selection matters.
- **Per-type checkboxes without auto-discovery** — requires manual registration of every analysis file. The readout handler already proved that GitHub folder scanning works reliably.
- **Fully automatic (no UI)** — removes researcher control. Some synthesis methods benefit from different input combinations.

### Implementation design

**New modal section** (rendered after Stakeholder Notes & Synthesis, before submit):

```
─────────────────────────────────────
Prior Analysis (optional)
[X] files available from prior synthesis

Select analysis files to include as context for this synthesis.
These are previously generated analyses from this study.

☑ Affinity Map — va-mobile-nav-2026-affinity-map-2026-04-30.md
☐ Journey Map — va-mobile-nav-2026-journey-map-2026-04-30.md
☑ Personas — va-mobile-nav-2026-personas-2026-04-30.md

ℹ Including prior analysis helps downstream synthesis reference
  cross-participant themes and validated patterns. If no prior
  analysis exists, the synthesis will work from session data alone.
─────────────────────────────────────
```

**Backend flow:**

1. In `handleStudySelectionChange`, after the three existing service calls, add a GitHub scan of analysis folders (same pattern as `readoutHandler.js` lines 316-340):

```js
const analysisScans = [
  { folder: '04-analysis/affinity-mapping', label: 'Affinity map' },
  { folder: '04-analysis/journey-mapping', label: 'Journey map' },
  { folder: '04-analysis/personas', label: 'Personas' },
  { folder: '04-analysis/usability-issues', label: 'Usability issues' },
  { folder: '04-analysis/jobs-to-be-done', label: 'Jobs to be done' },
  { folder: '04-analysis/design-opportunities', label: 'Design opportunities' },
  { folder: '04-analysis/service-blueprint', label: 'Service blueprint' },
];
```

2. For each folder, call `readFolderContents(path, GITHUB_REPO)` — returns `{ name, path }` per file. Deduplicate to latest version (same logic as readout handler).

3. Pass the analysis files to `researchSynthesisModal` as a new parameter.

4. In the modal, render them as a new checkbox section with help text.

5. On submission, selected analysis files get fetched via `fetchFileFromRepoByPath` and added to `combined_file_content` — same as session summaries and transcripts.

## 6. Help text design

### Section header

```
*Prior Analysis (optional)*
[X] files available from prior synthesis runs

Include previously generated analyses as context. Downstream synthesis methods
(personas, journey maps, design opportunities) produce better results when they
can reference cross-participant themes from prior analysis.
```

### Per-file-type guidance (shown as context element below each checkbox)

| File type | Help text |
|-----------|-----------|
| **Affinity map** | *Cross-participant themes and evidence clusters. Recommended for: personas, journey maps, design opportunities, service blueprints.* |
| **Journey map** | *Stage-by-stage user experience with pain points and opportunities. Recommended for: service blueprints, design opportunities.* |
| **Personas** | *Behavioral archetypes aggregated across participants. Recommended for: design opportunities, journey maps.* |
| **Usability issues** | *Prioritized interface problems with severity and fix recommendations. Recommended for: service blueprints, design opportunities.* |
| **Jobs to be done** | *Progress-focused user needs with When/Want/So statements. Recommended for: design opportunities, personas.* |
| **Design opportunities** | *HMW statements traced to research evidence. Recommended for: service blueprints.* |
| **Service blueprint** | *Frontstage/backstage process mapping with failure points. Rarely used as input to other synthesis.* |

### Empty state

```
No prior analysis files found for this study. The synthesis will work from
session data alone. Run affinity mapping or another analysis method first
to build a foundation for downstream synthesis.
```

### What happens if missing (general note below the section)

```
ℹ️ If no prior analysis is included, the synthesis will reference session
   summaries and transcripts only. Cross-participant patterns may be less
   prominent in the output.
```

## 7. Modal ordering recommendation

After adding the analysis section, the full modal section order would be:

1. **Study selector** (required)
2. **Analysis type** (required)
3. **Load Files button**
4. **Session Summaries** — fieldwork data
5. **Session Notes & Transcripts** — fieldwork data
6. **Stakeholder Notes & Synthesis** — stakeholder data
7. **Prior Analysis** (NEW) — synthesis-layer data
8. Submit

This follows the data hierarchy: fieldwork → stakeholder → synthesis. Each layer builds on the previous.

## 8. Future consideration: smart defaults

Once the modal supports analysis files, a natural enhancement is **analysis-method-aware defaults**:

| Selected method | Auto-check |
|----------------|------------|
| Journey mapping | Affinity map ✓ |
| Persona generation | Affinity map ✓ |
| Design opportunities | Affinity map ✓, Journey map ✓, Personas ✓ |
| Service blueprint | Journey map ✓, Stakeholder synthesis ✓ |
| JTBD | Affinity map ✓ |
| Usability issues | (none — works from session data) |
| Affinity mapping | (none — first synthesis step) |

This would be a follow-up enhancement, not part of the initial implementation. The initial version shows all available analysis files as unchecked, with help text guiding the researcher.
